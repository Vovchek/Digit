# ?? CBoundCtrls Data Structure Map

## Quick Reference Guide for Boundary Data Structures

---

## ?? Overview

`CBoundCtrls` manages **three types** of boundary data:

1. **Source Shapes** (User Input) ? `ArrEll`, `ArrRect`, `ArrPlg`
2. **Computed Contours** (Processed Output) ? `ArrContour`
3. **Temporary Drawing** (UI State) ? `CurBound`, `CurPlg`, `CustomDots`

## ?? Structure Details

### ?? Source Shapes (Input)

#### **CArrayXYEllipse ArrEll**
```cpp
class XYEllipse {
    double Ax, By;           // Semi-axes
    double Xc, Yc;           // Center
    double Fi;               // Rotation angle
    int TypeLimits;          // EXTERNAL or INTERNAL
    int TypeSystCoor;        // MEASURING or NORMALISED
};
```
**Purpose**: Store user-drawn ellipses/circles  
**When set**: User draws with ellipse tool  
**TypeLimits**: EXTERNAL (aperture) or INTERNAL (obstruction)

---

#### **CArrayXYRect ArrRect**
```cpp
class XYRect {
    double XLeft, XRight;
    double YTop, YBottom;
    int TypeLimits;          // EXTERNAL or INTERNAL
    int TypeSystCoor;
};
```
**Purpose**: Store user-drawn rectangles  
**When set**: User draws with rectangle tool  
**TypeLimits**: EXTERNAL (aperture) or INTERNAL (obstruction)

---

#### **CArrayXYPolygon ArrPlg**
```cpp
class XYPolygon : public XYBrokenLine {
    CArrayXYPoint ArrPnt;    // Vertices
    int TypeLimits;          // EXTERNAL or INTERNAL
    int TypeSystCoor;
};
```
**Purpose**: Store user-drawn polygons  
**When set**: User draws with polygon tool  
**TypeLimits**: EXTERNAL (aperture) or INTERNAL (obstruction)

---

### ?? Computed Contours (Output)

#### **CArrayXYPolygon ArrContour**
```cpp
// Generated by CalcContour(ArrEll, ArrRect, ArrPlg, ArrContour)
```

**Purpose**: Processed visible boundary contours  
**When set**: `FormBoundsOnLoadFile()` ? `CalcContour()`  
**Contents**: 
- All source shapes converted to polygons
- Occlusion/visibility processed
- Properly closed contours
- TypeLimits set (EXTERNAL/INTERNAL)

**Why use it**:
- ? Unified format (all polygons)
- ? Already processed for visibility
- ? Consistent representation
- ? Ready for pixel testing

---

### ?? Temporary Drawing State (UI)

#### **CRect CurBound**
```cpp
CRect CurBound;  // {left, top, right, bottom}
```
**Purpose**: Preview rectangle while user is dragging  
**When set**: During interactive rectangle drawing  
**Cleared**: When drawing finalized ? added to `ArrRect`

---

#### **CArray<CPoint> CurPlg**
```cpp
CArray<CPoint, CPoint> CurPlg;
```
**Purpose**: Preview polygon while user is drawing  
**When set**: Each click adds a vertex  
**Cleared**: When polygon closed ? converted to `XYPolygon` ? added to `ArrPlg`

---

#### **CArray<CPoint> CustomDots**
```cpp
CArray<CPoint, CPoint> CustomDots;
CPoint CustomDot;
```
**Purpose**: Store custom polygon vertices during editing  
**When set**: User places individual points  
**Cleared**: When finalized into polygon

---

### ?? Metadata

#### **int ExtBoundType / InsBoundType**
```cpp
int ExtBoundType;  // BOUND_ROUND, BOUND_ELLIPSE, BOUND_RECT, BOUND_POLYGON
int InsBoundType;  // Same values, or -1 if none
```

**Values**:
```cpp
#define BOUND_ROUND    0  // Circle
#define BOUND_ELLIPSE  1  // Ellipse
#define BOUND_RECT     2  // Rectangle
#define BOUND_POLYGON  3  // Polygon
```

**Purpose**: Track what type of boundary is active  
**Used in**: `CreateRedCenters()` to decide masking strategy

## ?? When to Use Each Structure

### ? Use **Source Arrays** (ArrEll/ArrRect/ArrPlg) When:
- Saving/loading file data
- Displaying shapes in UI
- Editing individual shapes
- Storing user input

### ? Use **ArrContour** When:
- Testing pixel visibility (`isPupil()`)
- Processing boundaries for algorithms
- Generating scan-line masks
- Uniform polygon representation needed

### ? Use **buf_line** When:
- Fast per-line X boundary lookup
- Simple shapes (ellipse, rect, circle)
- Pixel-by-pixel scanning

### ? Don't Use:
- **CurBound/CurPlg**: Only for UI interaction, not computation
- **Source arrays in CreateRedCenters**: Use ArrContour instead!

## ?? Common Mistakes

### ? Mistake #1: Testing Source Arrays in CreateRedCenters
```cpp
// WRONG:
if (isPupil(P, pB->ArrEll, pB->ArrRect, pB->ArrPlg))  // ?
```
**Problem**: Source shapes not processed, mixed types

```cpp
// RIGHT:
if (isPupil(P, pB->ArrContour))  // ?
```
**Why**: ArrContour already processed and unified

---

### ? Mistake #2: Using nContours as Complexity Flag
```cpp
// WRONG:
if (nContours > 2)  // ? Assumes count = complexity
```
**Problem**: Single polygon has `nContours = 1` but needs masking

```cpp
// RIGHT:
bool useComplexMasking = (ExtBoundType == BOUND_POLYGON || InsBoundType == BOUND_POLYGON);
if (useComplexMasking)  // ?
```
**Why**: Shape type determines complexity, not count

---

### ? Mistake #3: Forgetting CalcContour()
```cpp
// WRONG: Use source arrays directly
CreateRedCenters();
if (isPupil(P, ArrPlg))  // ? ArrContour not populated!
```

```cpp
// RIGHT: Call FormBoundsOnLoadFile() first
pB->FormBoundsOnLoadFile();  // Calls CalcContour()
CreateRedCenters();
if (isPupil(P, pB->ArrContour))  // ? ArrContour populated
```

## ?? Best Practices

1. **Always populate ArrContour before using it**
   ```cpp
   pB->FormBoundsOnLoadFile();  // Calls CalcContour()
   ```

2. **Use ArrContour for pixel testing**
   ```cpp
   if (isPupil(P, pB->ArrContour))  // ? Correct
   ```

3. **Check boundary type, not contour count**
   ```cpp
   bool useComplexMasking = (ExtBoundType == BOUND_POLYGON || InsBoundType == BOUND_POLYGON);
   ```

4. **Keep source arrays for save/load**
   ```cpp
   IntInfo.ArrEll.Append(pB->ArrEll);   // Save original shapes
   IntInfo.ArrRect.Append(pB->ArrRect);
   IntInfo.ArrPlg.Append(pB->ArrPlg);
   ```

5. **Don't use temporary structures in algorithms**
   ```cpp
   // ? Never use CurBound/CurPlg in computation
   // ? Only for UI preview
   ```
