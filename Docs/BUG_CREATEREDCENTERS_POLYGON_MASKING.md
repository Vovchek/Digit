## The Bugs

**File**: `DigitMode/DigitInfo.cpp`

**Lines**: ~388-405

There were **TWO bugs** in the same section of code:

### Bug #1: Incorrect Condition (Wrong Logic)
### Bug #2: Wrong Data Structure (Conceptual Error)

## Bug #1: Incorrect Masking Condition

### Incorrect Code
```cpp
int nContours = pB->ArrContour.GetSize();
XYPoint P;
for (int iy = begY; iy < endY; iy++) {
    int n = -1;
    for (auto iCol = 0; iCol < pI->m_pDIB->m_dwWidth; iCol++) {
        // ...read pixel...
        ++n;
        if (nContours > 2) {  // ? BUG #1: Wrong condition!
            P.X = iCol; P.Y = iy;
            if (isPupil(P, pB->ArrEll, pB->ArrRect, pB->ArrPlg))
                line[n] = inv_line[n] = ((unsigned char)rgbPix.rgbRed);
            else
                line[n] = inv_line[n] = 0;
        }
        else {
            line[n] = inv_line[n] = ((unsigned char)rgbPix.rgbRed);
        }
    }
```

### Root Cause Analysis

**Condition**: `if (nContours > 2)`
- `nContours = pB->ArrContour.GetSize()` = number of contours generated by `CalcContour()`
- For **1 EXTERNAL polygon boundary**: `nContours = 1`
- `1 > 2` is **FALSE** ? Falls into `else` branch
- **Result**: No `isPupil()` masking applied ? ALL pixels processed!

### Why nContours Can Be 1

**Scenario 1**: Single polygon external boundary
```cpp
ArrEll.GetSize() = 0
ArrRect.GetSize() = 0
ArrPlg.GetSize() = 1  // One polygon with TypeLimits=EXTERNAL

CalcContour(ArrEll, ArrRect, ArrPlg, ArrContour, NPntMax);
// Result: ArrContour.GetSize() = 1 (single EXTERNAL contour)
```

**Scenario 2**: Single ellipse external boundary
```cpp
ArrEll.GetSize() = 1  // One ellipse with TypeLimits=EXTERNAL
ArrRect.GetSize() = 0
ArrPlg.GetSize() = 0

CalcContour(ArrEll, ArrRect, ArrPlg, ArrContour, NPntMax);
// Result: ArrContour.GetSize() = 1
```

**Scenario 3**: Ellipse + internal hole
```cpp
ArrEll.GetSize() = 2  // One EXTERNAL + one INTERNAL
ArrRect.GetSize() = 0
ArrPlg.GetSize() = 0

CalcContour(ArrEll, ArrRect, ArrPlg, ArrContour, NPntMax);
// Result: ArrContour.GetSize() = 2
// Condition `nContours > 2` is still FALSE!
```

## Bug #2: Using Wrong Data Structure

### The Problem

Even after fixing Bug #1, the code tested against the **wrong arrays**:

```cpp
if (isPupil(P, pB->ArrEll, pB->ArrRect, pB->ArrPlg))  // ? BUG #2: Wrong arrays!
```

**Why this is wrong**:
- `ArrEll`, `ArrRect`, `ArrPlg` are **source shapes** (user input)
- `ArrContour` contains **computed visible contours** (CalcContour output)
- We should test against `ArrContour`, not source shapes!

---

## Understanding the Data Structures

### **CBoundCtrls::ArrEll / ArrRect / ArrPlg** (Source Shapes)
```cpp
CBoundCtrls::ArrEll     // User-drawn ellipses
CBoundCtrls::ArrRect    // User-drawn rectangles  
CBoundCtrls::ArrPlg     // User-drawn polygons
```
- **Purpose**: Define the boundary geometry
- **When set**: User draws shapes via UI
- **TypeLimits**: Each shape has EXTERNAL or INTERNAL flag
- **Contents**: Original geometric primitives

### **CBoundCtrls::ArrContour** (Computed Contours)
```cpp
CBoundCtrls::ArrContour  // Result of CalcContour(ArrEll, ArrRect, ArrPlg, ...)
```
- **Purpose**: Actual visible boundary segments after occlusion processing
- **When set**: Called in `FormBoundsOnLoadFile()` ? `CalcContour()`
- **Contents**: XYPolygon objects representing visible contours
- **Why use it**: Already processed for visibility and converted to polygons!

### **CBoundCtrls::CurBound** (Temporary)
```cpp
CBoundCtrls::CurBound   // Temporary rectangle while user is drawing
```
- **Purpose**: Preview rectangle during interactive drawing
- **Not used in computation**

### **Data Flow Diagram**

```
User Input:
  ArrEll (ellipses)  ???
  ArrRect (rects)    ????? CalcContour() ??? ArrContour (polygons)
  ArrPlg (polygons)  ???                         ?
                                          Used in CreateRedCenters()
```

## Why Both Bugs Matter

### Scenario: Single Polygon External Boundary

**User action**: Draw one polygon as external aperture

**Data state**:
```cpp
ArrEll.GetSize() = 0
ArrRect.GetSize() = 0
ArrPlg.GetSize() = 1      // One polygon, TypeLimits = EXTERNAL
ArrContour.GetSize() = 1  // CalcContour creates one contour polygon

ExtBoundType = BOUND_POLYGON
```

**Bug #1 effect** (`nContours > 2`):
- `ArrContour.GetSize() = 1`
- `1 > 2` is FALSE
- ? **No masking applied at all!**

**Bug #2 effect** (testing `ArrPlg` instead of `ArrContour`):
- Even if Bug #1 was fixed, code would test against **source polygon**
- But should test against **computed contour polygon**
- **Difference**: CalcContour may modify the polygon (close it, resample points, etc.)

## The Complete Fix

### Fixed Code

```cpp
int nContours = pB->ArrContour.GetSize();
XYPoint P;
bool useComplexMasking = (pB->ExtBoundType == BOUND_POLYGON || pB->InsBoundType == BOUND_POLYGON);
for (int iy = begY; iy < endY; iy++) {
    int n = -1;
    for (auto iCol = 0; iCol < pI->m_pDIB->m_dwWidth; iCol++) {
        idx = ((yDIB - iy) * pI->m_pDIB->m_dwWidth + iCol);
        Pixel = pI->m_pDIB->m_lpSrcBits[idx];
        rgbPix.rgbRed = Pixel;
        ++n;
        if (useComplexMasking) {  // ? FIX #1: Check boundary type, not contour count
            P.X = iCol; P.Y = iy;
            // ? FIX #2: Test against ArrContour, not source arrays
            if (isPupil(P, pB->ArrContour))
                line[n] = inv_line[n] = ((unsigned char)rgbPix.rgbRed);
            else
                line[n] = inv_line[n] = 0;
        }
        else {
            line[n] = inv_line[n] = ((unsigned char)rgbPix.rgbRed);
        }
    }
```

### Changes Summary

| Aspect | Before | After |
|--------|--------|-------|
| **Condition** | `nContours > 2` | `ExtBoundType == POLYGON ? InsBoundType == POLYGON` |
| **Logic** | ? Checks contour count | ? Checks boundary shape type |
| **Test against** | ? `isPupil(P, ArrEll, ArrRect, ArrPlg)` | ? `isPupil(P, ArrContour)` |
| **Data used** | ? Source shapes | ? Computed contours |

## Why Use ArrContour Instead of Source Arrays?

### Advantages of ArrContour

1. **? Already processed**: CalcContour has computed visible segments
2. **? Unified format**: All shapes converted to polygons
3. **? Occlusion handled**: Invisible parts already removed
4. **? Properly closed**: Contours are closed polygons
5. **? Consistent**: Single data structure for all boundary types

### Problems with Source Arrays

1. **? Mixed types**: Need to test ellipses, rects, and polygons separately
2. **? Raw input**: Not processed for visibility
3. **? Redundant**: CalcContour already did the work!
4. **? Inconsistent**: Different semantics for each type

### Example

**Input** (source):
```cpp
ArrEll[0] = Ellipse(center=200,200, a=100, b=80, EXTERNAL)
ArrPlg[0] = Polygon(points=[...], INTERNAL)
```

**After CalcContour** (computed):
```cpp
ArrContour[0] = Polygon(points=[...500 points...], EXTERNAL)  // Ellipse converted
ArrContour[1] = Polygon(points=[...300 points...], INTERNAL) // Original polygon
```

**CreateRedCenters should use**: `ArrContour` (already processed!)

## Why Original Code Used Source Arrays

### Developer's Intent (Guessed)

The original developer probably thought:
1. "Use `nContours` to detect complexity" ? Bug #1
2. "Test against original shapes for accuracy" ? Bug #2

### Why This Failed

**For Bug #1**:
- Contour count ? Complexity indicator
- A single polygon is complex but has `nContours = 1`
- Check should be **shape type**, not contour count

**For Bug #2**:
- Source shapes are **input**, not **processed output**
- CalcContour already converted everything to contours!
- Testing source shapes is **redundant and inconsistent**

- **This bug #2**: `CreateRedCenters()` tests against wrong data structure!

All three bugs involve `isPupil()`, but in different contexts:
- CalcContour: Tests **contour boundary points**
- CreateRedCenters: Tests **interior pixel positions**

### Root Causes

1. **Bug #1**: Using **contour count** as a proxy for **complexity** is incorrect
2. **Bug #2**: Testing **source shapes** instead of **computed contours** is redundant

1. **Fix #1**: Replace `nContours > 2` with explicit check for `BOUND_POLYGON`
2. **Fix #2**: Replace `isPupil(P, ArrEll, ArrRect, ArrPlg)` with `isPupil(P, ArrContour)`

- **Fix #2**: Ensures correct and consistent boundary testing
